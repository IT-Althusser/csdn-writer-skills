# Style Rules

## 风格约束

不要出现这些写法：

- “你的笔记里提到”
- “我在笔记里写过”
- “这篇文章我打算”
- “表面上看……其实……”
- “不是……而是……”
- “通常不是……而是……”
- “往往不是……而是……”
- “真正有用的不是……而是……”
- “很多人会以为……但真正……”
- “项目里的做法很清楚，一共分三步”
- “这个地方值得单独讲清楚”
- “这里最值得记住的是”
- “真正把代码串起来之后会发现”
- “下面是只使用 StringRedisTemplate 普通命令的实现”
- “项目里的实现和下面的代码一致”
- “先补充几个 import”“把以下代码放进某个类中”

原因：

- 这些句子会暴露写作过程，削弱面向读者的表达
- 容易制造 AI 味和空洞铺垫
- 会把技术文章写成自说自话的讲稿
- 会把技术文章写成代码讲义或编辑步骤，读者看到的是作者准备展示什么，而不是代码解决什么问题

代码块前后的文字直接说明读者需要理解的行为。避免介绍接下来的代码、说明代码摘自哪里、指挥读者如何拼装代码。

例如，不写：

> 下面是只使用 StringRedisTemplate 普通命令的实现。加锁部分与项目里的 SimpleRedisLock 一致；释放部分采用先读锁值、再判断归属、最后删除的阶段性写法：

可以改成：

> 加锁时，setIfAbsent 在写入锁标识的同时设置过期时间。释放时先读取锁值，只有标识属于当前线程才删除：

判断标准是句子是否解释了场景、机制、输入输出或风险。若句子只预告代码片段、交代材料来源或安排编辑步骤，就重写为技术行为说明。不要把“下面”“项目里”等词当作机械禁词；只有当它们构成材料导读或作者自述时才需要删除。

只有在确实需要纠正易错点时，才允许使用一次“错误认知对比”表达。
如果用户已经明确指出这类句式 AI 味重或要求去掉，就一律禁用，不再使用其任何变体。

## 输出习惯

- 默认输出 Markdown 正文，不要把整篇博客包在总代码块里
- 如果需要保存成文件，默认保存到 `D:\codex-content\<当前日期>`
- 前言要短，但必须完成引入：用 2-3 句话先概括核心内容，再交代这些内容如何串成主线；知识点或课程笔记文章可采用“这篇整理……，包括……；这些内容串起来可以完成……”的自然表达，功能文章直接说明目标和代码需求。
- 前言通常不超过 120 字，内容较短时可以更短；不要写背景常识、学习感受、目录复述或“本文将……”式预告。
- 开头两三句话内必须进入功能或知识点本身
- 总结用 1 段收束：指出文章解决的问题；有对应内容时再提炼 1 个可迁移的判断方法或易错点，没有就用 1-2 句收束关键结论。不要复读目录、逐项重述正文、写空泛方法论或追加“以后我们还可以……”等尾巴。
- 全文不要为了显得完整而扩写：删除不增加事实、步骤、边界或验证价值的过渡句和感想句，合并重复解释，优先保证信息密度。
- 代码后必须解释变量、参数、返回值、配置项、SQL 条件或调用链
- 少用连续设问、反问、口号式总结和“首先其次最后”的机械句式
- 正文要有博客口吻：围绕读者遇到的问题自然推进，少用说明书式定义、材料转述和作者自述
- 版本只在影响兼容性、行为或排查时提及；不要写“直接版本中”“本版本中新增”“当前版本中就是这样”等生硬句式，要把版本放进具体项目依赖、现象和验证方法里

## SQL / 配置规则

- MySQL / SQL 主题文章中的 SQL 语句统一使用小写关键字
- 例如 `create`、`select`、`from`、`where`、`with check option`
- `application.yml`、`application-dev.yml`、密码、`AccessKey`、`Secret` 等必须脱敏
- 同时说明占位符、环境激活、yml 缩进和取值链路

## 格式控制

文章里可以使用引用、加粗和反引号，但必须克制。默认采用“自然段 + 少量加粗”的博客排版，反引号从严。

- 引用：只用于用户笔记原话、官方文档结论、关键提醒或一条核心判断
- 加粗：只用于关键结论、步骤名、字段名解释、注意事项
- 反引号：只用于真实代码标识、注解、类名、方法名、字段名、文件路径、命令、配置项、SQL 片段、接口路径
- 正文默认采用“加粗优先，反引号从严”

交付前格式自检：

1. 引用、加粗、反引号不强制三者都出现，只在真正有用时使用
2. 分别统计引用块数量、加粗片段数量、内联反引号片段数量
3. 引用通常不超过 2 个；正文内联反引号默认不超过 3 个，确需保留精确标识时最多 5 个；加粗只留下关键重点
4. 代码块里的反引号围栏和代码块内容本身不计入内联反引号数量
5. 自检不需要把统计表写进正文，除非用户明确要求展示
6. 交付前二次检查并主动压缩反引号；优先保留方法名、注解名、接口路径这类容易混淆的标识，其余技术名词改用自然中文或少量加粗
