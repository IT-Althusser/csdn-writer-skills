# 纯文字课程笔记博客化

用于“给一份纯文字课程笔记、课堂截图和参考文章，写成 CSDN 博客”这一类任务。目标是保留课程知识路线，同时把压缩提纲改写成读者可连续阅读的知识点文章。

## 输入分工

| 材料 | 用途 | 禁止事项 |
| --- | --- | --- |
| 用户笔记正文 | 章节顺序、核心概念、原始结论 | 不得把未出现的独立主题塞进文章 |
| 用户提供的截图 | 图中的字段、流程、对比、数值和术语 | 不得编造截图外的运行现象 |
| 同主题参考文章 | 核验可补充事实、学习解释深度 | 不得整段改写或照搬图片 |
| 异章节参考文章 | 学习段落展开、目录组织、解释粒度 | 不得把其知识点作为当前文章事实 |

先列出笔记中的一级、二级知识点和每张图片对应的主题，再从中确定 3 至 5 个需要展开的重点。优先选择能串起全文的机制、最易混淆的概念、具有明确过程的协议或带有字段/计算关系的部分。

## 写作路线

1. 用 2-3 句话完成前言引入：先概括本章覆盖的核心内容，再说明这些内容如何串成知识路线并解决一个具体问题。可以写成“这篇整理……，包括……；这些内容串起来可以完成……”的自然表达，不称其为“笔记整理”，也不复述目录。
2. 按用户材料的章节顺序写，但不机械逐条复述。
3. 每个普通知识点用一段交代定义和作用；每个重点知识点至少增加一个解释单元。
4. 把图片放在对应小节之后，使用面向读者的图题，例如“IPv4 分类编址”或“OSPF 区域与路由器角色”，不要写“课堂图”“原图”。
5. 用一段短总结收束主线，指出本章解决的问题；有对应内容时再提炼一个可迁移的判断方法或易错点。不复读目录，不扩展后续计划，不写空泛感想。

可用的解释单元如下，按材料选择，不要求全部出现：

- **作用与位置**：说明该概念解决哪一个问题，与前后概念怎样衔接。
- **流程拆解**：将“建立、交换、更新、计算、转发”之类的过程拆成连续动作。
- **关键区别**：对笔记中本已成对出现的概念进行比较，例如静态/动态路由、RIP/OSPF、虚电路/数据报服务。
- **字段或数值**：解释用户截图或正文中已经出现的字段、前缀、端口、时间、跳数、地址范围或公式。
- **小型例子**：只为说明已有规则而写，例如最长前缀匹配、默认网关与下一跳；例子不得引入新的协议主题。
- **适用边界**：解释笔记已经出现的“适合小规模”“不能大于 16”“找不到路由”等限制意味着什么。

## 参考文章处理

先确认参考文章的章节和主题是否与用户材料一致。

- 同主题：抽取可以核验且直接服务当前小节的定义、过程或边界，改用自己的话写入；参考资料区保留链接。
- 异章节：只借鉴“定义后解释作用、过程按步骤展开、图文紧邻、段落由短到长”的写法；不把其中事实、示例、协议或术语写入正文，也无需把该链接列为事实来源。

无论哪种情况，都不能复制参考文章的段落、标题包装或图片。

## 正文禁区

正文禁止出现材料来源话术，包括但不限于：

- 笔记中、课堂图、课程资料显示、根据材料；
- 我看到的图片、你提供的笔记、本文根据某某整理；
- 为了补充内容而新开与原章节无关的主题。

允许在文末“参考资料”列出链接，但不要在正文反复证明材料来源。

## 交付前验收

逐项检查：

1. 标题、前言、主体和总结是否围绕同一章主题。
2. 一级知识点是否保持用户材料的顺序，且没有跨章主题。
3. 是否已为 3 至 5 个重点补上具体解释，而非只把每个点平均加长。
4. 前言是否先完成主题引入，再交代知识路线；总结是否只收束主线并留下方法或易错点；全文是否删除了不增加信息的重复段落。
5. 每一处补充事实能否追溯到用户正文、截图或同主题已核验参考文。
6. 图片是否存在、是否紧邻正确小节、图题是否面向读者。
7. 正文是否完全没有“笔记”“课堂图”“根据材料”等来源话术。
8. 是否完成链接、禁用语、图片引用、格式标记和交付文件存在性检查。
